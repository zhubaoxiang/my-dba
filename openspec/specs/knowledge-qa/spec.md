## Requirements
### Requirement: 问答会话

系统 SHALL 支持多轮问答会话：每次提问归属一个会话，会话内保留历史消息并可回看。会话与消息 MUST 持久化，MUST 支持软删除。

#### Scenario: 新建会话并提问

- **WHEN** 用户发起提问且未指定会话
- **THEN** 系统创建一个新会话，记录该问题与回答，并返回会话标识

#### Scenario: 追加提问沿用上下文

- **WHEN** 用户在已有会话中继续提问
- **THEN** 系统把该会话的历史消息纳入上下文后再作答

#### Scenario: 查看历史

- **WHEN** 用户查询某会话
- **THEN** 系统按时间顺序返回该会话的消息，每条标注提问者、回答内容与来源

#### Scenario: 上下文长度受限

- **WHEN** 某会话的历史超出上下文预算
- **THEN** 系统 MUST 按既定策略截断（保留最近若干轮），MUST NOT 因超长而调用失败

#### Scenario: 软删除会话

- **WHEN** 删除一个会话
- **THEN** 系统软删除该会话及其消息，列表查询不再返回

### Requirement: 检索增强回答

系统 SHALL 优先基于知识库检索结果作答：把检索到的片段作为依据交给模型，并在回答中标注引用来源。

#### Scenario: 命中知识库时据其作答

- **WHEN** 提问在指定知识库中检索到高于阈值的片段
- **THEN** 回答 MUST 基于这些片段组织，并标注引用了哪些文档

#### Scenario: 回答可溯源

- **WHEN** 用户查看一条基于知识库的回答
- **THEN** 该回答带有可追溯到具体文档（及片段）的来源信息

#### Scenario: 不得凭空编造来源

- **WHEN** 回答中给出了引用来源
- **THEN** 每个来源 MUST 对应本次检索实际返回的片段，MUST NOT 出现未被检索到的来源

### Requirement: 通用模型回答与自动回退

系统 SHALL 在知识库未配置或检索无命中时回退到通用大模型作答，并 MUST 在回答中明确标注本次回答未经知识库支撑。

#### Scenario: 未配置知识库时回退

- **WHEN** 提问时没有启用中的知识库
- **THEN** 系统调用通用大模型作答，并标注该回答未使用知识库

#### Scenario: 检索无命中时回退

- **WHEN** 指定知识库检索无命中且模式为自动
- **THEN** 系统回退到通用大模型作答，并标注未找到相关资料

#### Scenario: 回退不得静默

- **WHEN** 发生了回退
- **THEN** 响应中 MUST 体现「本次回答未基于知识库」，MUST NOT 让使用者误以为答案有文档依据

#### Scenario: 未配置对话模型

- **WHEN** 没有生效中的对话模型且用户提问
- **THEN** 系统返回明确错误，提示需先配置并生效一条对话模型

#### Scenario: 未配置嵌入模型

- **WHEN** 有生效的对话模型但没有生效的嵌入模型，且提问需要检索知识库
- **THEN** 系统返回明确错误，提示需配置并生效一条嵌入模型
- **AND** MUST NOT 报成服务器错误——这是配置问题，使用者需要知道去改哪里

### Requirement: 强制回答模式

提问 SHALL 支持指定回答模式：自动、仅知识库、仅通用模型。模式为「仅知识库」且无命中时，系统 MUST 如实告知未找到，MUST NOT 改用通用模型作答。

#### Scenario: 仅知识库模式

- **WHEN** 以「仅知识库」模式提问且检索无命中
- **THEN** 系统返回「未在知识库中找到相关内容」，且 MUST NOT 给出模型自行生成的答案

#### Scenario: 仅通用模型模式

- **WHEN** 以「仅通用模型」模式提问
- **THEN** 系统跳过检索直接调用模型，并在回答中标注未使用知识库

#### Scenario: 自动模式为默认

- **WHEN** 提问时未指定模式
- **THEN** 采用自动模式（先检索，命中则据文档作答，无命中则回退）

### Requirement: Agent 工具调用

问答 SHALL 由 langchain + langgraph 组成的单 agent 编排，agent MAY 自主决定调用工具及其次数。工具集至少包含：检索知识库、查询已纳管数据源的表结构。系统 MUST 限制最大步数，避免无限调用。

#### Scenario: 按问题选择工具

- **WHEN** 提问涉及已纳管库的表结构
- **THEN** agent 可调用表结构查询工具获取真实结构后再作答

#### Scenario: 组合多个来源

- **WHEN** 提问同时涉及文档知识与表结构
- **THEN** agent 可在同一次回答中调用多个工具并综合结果

#### Scenario: 达到最大步数

- **WHEN** agent 调用工具的步数达到配置上限
- **THEN** 系统终止继续调用并基于已有信息作答，MUST NOT 无限循环

#### Scenario: 工具执行失败

- **WHEN** 某个工具执行失败（如指定数据源不存在）
- **THEN** agent 收到可读的失败信息并继续作答，MUST NOT 让整个问答失败

#### Scenario: 回答标注实际调用

- **WHEN** agent 在作答过程中调用了工具
- **THEN** 回答中 MUST 体现实际调用过的工具，供使用者判断可信度

### Requirement: 问答界面

系统 SHALL 提供前端问答页面，包含会话列表、多轮对话区、提问输入、知识库选择与回答模式选择，并展示回答的来源标注。页面 SHALL 以流式方式呈现回答，并在生成过程中提供中止操作与过程状态展示。

#### Scenario: 问答页面可用

- **WHEN** 用户进入问答页面
- **THEN** 页面展示会话列表与对话区，提供提问输入、知识库选择与模式选择

#### Scenario: 来源可见

- **WHEN** 回答带有知识库来源
- **THEN** 页面展示所引用的文档，并可查看对应片段

#### Scenario: 回退提示可见

- **WHEN** 回答由通用模型回退产生
- **THEN** 页面明确展示「未基于知识库」的提示

#### Scenario: 回答逐段呈现

- **WHEN** 回答正在生成
- **THEN** 页面 MUST 随内容到达逐步呈现，MUST NOT 等到全部生成完毕才显示

#### Scenario: 生成过程可中止

- **WHEN** 回答正在生成
- **THEN** 页面 MUST 提供中止操作，使用者可随时停止

#### Scenario: 过程状态可见

- **WHEN** 系统输出检索或工具执行的进度提示
- **THEN** 页面 MUST 展示该进度，使等待过程可见

#### Scenario: 不完整回答可识别

- **WHEN** 用户回看一条被中断的回答
- **THEN** 页面 MUST 标明该回答不完整

### Requirement: 流式回答输出

系统 SHALL 提供一个流式问答接口，在生成回答的过程中分次输出文本，使使用者无需等待整段生成完毕即可看到内容。该接口 MUST 与一次性返回的同步接口并存，同步接口的请求参数与响应结构 MUST NOT 改变。

#### Scenario: 分次输出回答

- **WHEN** 用户通过流式接口提问且通过预检
- **THEN** 系统 MUST 在生成过程中分多次输出回答文本片段，MUST NOT 等到全部生成完毕才一次返回

#### Scenario: 与同步接口并存

- **WHEN** 调用方需要一次性取得完整响应
- **THEN** 原有的同步问答接口 MUST 仍然可用，且其请求参数、响应结构与既有行为 MUST NOT 改变

#### Scenario: 成功回答脱离统一响应格式

- **WHEN** 流式接口通过预检并开始输出回答
- **THEN** 响应体 MUST NOT 采用 `{code, message, data}` 的统一响应结构，且 MUST 携带可流式传输的内容类型

#### Scenario: 预检失败仍按统一格式返回

- **WHEN** 请求在开始输出前即可判定失败（参数不合法、会话不存在、未配置对话或嵌入模型、向量服务不可用）
- **THEN** 系统 MUST 按统一响应格式返回错误，并在响应体中给出对应的业务错误码
- **AND** MUST NOT 在已经开始输出之后才发现这些失败

### Requirement: 流式过程进度提示

系统 SHALL 在流式回答过程中输出面向使用者的中间进度，使检索与工具执行阶段可见。进度信息 MUST 与回答正文以可区分的事件类型送达，MUST NOT 泄露工具入参、原始返回内容或内部实现细节。

#### Scenario: 工具执行阶段可见

- **WHEN** agent 开始检索知识库或查询已纳管数据源的表结构
- **THEN** 系统 MUST 先输出一条面向使用者的进度提示，再继续执行

#### Scenario: 进度与正文分离

- **WHEN** 同一次流式回答中既有进度提示又有回答正文
- **THEN** 二者 MUST 以可区分的事件类型送达，回答正文中 MUST NOT 混入进度文案

#### Scenario: 进度不泄露内部细节

- **WHEN** 系统输出进度提示
- **THEN** 提示内容 MUST NOT 包含工具名称之外的入参、检索返回的原始片段或提示词内容

### Requirement: 流式生成的中断与部分保留

系统 SHALL 允许使用者中止流式生成。生成被中止或异常断连时，已生成的内容 MUST 保留并可回看，且 MUST 标注该回答不完整。

#### Scenario: 主动停止生成

- **WHEN** 使用者在生成过程中主动停止
- **THEN** 系统 MUST 停止生成，并把已输出的内容保存为该轮回答

#### Scenario: 异常断连

- **WHEN** 生成过程中客户端断开连接
- **THEN** 系统 MUST 保存已生成的内容，MUST NOT 丢弃

#### Scenario: 不完整回答可识别

- **WHEN** 回看一条被中断的回答
- **THEN** 该回答 MUST 带有「不完整」的标记，使用者 MUST NOT 将其误认为完整回答

#### Scenario: 完整回答不带中断标记

- **WHEN** 回答正常生成完毕
- **THEN** 该回答 MUST 被标记为完整

#### Scenario: 提问先于生成落库

- **WHEN** 流式提问通过预检并开始生成
- **THEN** 用户的提问 MUST 在开始生成前持久化，使生成中断时提问不会一并丢失

### Requirement: 流式回答的错误处理

开始输出之后发生的错误 MUST 通过流内的错误事件送达使用者，MUST NOT 静默断开连接，也 MUST NOT 让该次流式响应看起来是正常结束。

#### Scenario: 开流后失败推送错误事件

- **WHEN** 回答生成过程中发生错误
- **THEN** 系统 MUST 推送一条错误事件说明失败原因，并结束该次流式响应

#### Scenario: 出错后保留已有内容

- **WHEN** 生成过程中出错并中止
- **THEN** 已生成的内容 MUST 保存并标记为不完整

#### Scenario: 服务故障不得伪装成无命中

- **WHEN** 向量服务不可用导致检索失败
- **THEN** 系统 MUST NOT 将其表现为「知识库中没有相关内容」，MUST 以可区分的错误形式告知使用者

### Requirement: 数据源范围问答

系统 SHALL 允许提问时指定一个已纳管数据源，并在该数据源的最近一次元数据快照范围内回答表数量、表结构与健康问题。数据源 MUST 作为可选上下文与知识库并存，MUST NOT 连接被纳管数据库执行实时查询。

#### Scenario: 选择数据源后询问表数量

- **WHEN** 用户选择某数据源并提问「这个环境有多少张表」
- **THEN** agent MUST 调用数据源概况工具，并基于最新快照给出表数量
- **AND** MUST NOT 根据模型自身记忆编造数量

#### Scenario: 同时选择知识库和数据源

- **WHEN** 用户同时选择知识库与数据源，提问同时涉及文档知识与环境事实
- **THEN** agent MAY 在同一次回答中调用知识库检索与数据源工具，并综合结果

#### Scenario: 知识库无命中但已选数据源

- **WHEN** 自动模式下知识库检索无命中，且本次提问指定了数据源
- **THEN** 系统 MUST 进入 agent 并调用数据源工具作答
- **AND** MUST NOT 直接回退到通用模型

#### Scenario: 只选数据源

- **WHEN** 用户只选择数据源、不选择知识库
- **THEN** 系统 MUST 直接进入 agent，使用数据源工具作答
- **AND** MUST NOT 因缺少知识库而跳过数据源

#### Scenario: 未指定数据源

- **WHEN** 提问未指定数据源
- **THEN** 系统行为 MUST 与既有问答一致，MUST NOT 构造数据源工具

#### Scenario: 仅知识库模式

- **WHEN** 回答模式为「仅知识库」且指定了数据源
- **THEN** 系统 MUST NOT 调用任何数据源工具
- **AND** MUST 只依据知识库作答

#### Scenario: 数据源不存在或未采集

- **WHEN** 提问指定的数据源不存在或已软删除
- **THEN** 系统 MUST 返回明确的配置错误，提示重新选择数据源
- **WHEN** 数据源存在但尚未采集
- **THEN** 工具 MUST 如实告知尚未采集，MUST NOT 编造表或问题

### Requirement: 数据源诊断工具

系统 SHALL 为 agent 提供数据源概况与问题清单工具。概况 MUST 包含表数量、模式数量、问题总数与严重级别分布、最近采集时间；问题清单 MUST 支持按表名和严重级别过滤，MUST 排除已静音的问题，并 MUST 限制返回条数与单条文本长度。

#### Scenario: 查看整体概况

- **WHEN** agent 调用数据源概况工具
- **THEN** 返回表数量、模式数量、各级别问题数量、问题总数与最近采集时间

#### Scenario: 查看问题清单

- **WHEN** 用户提问「哪些表有明显问题」
- **THEN** agent MUST 调用问题清单工具，并基于返回的问题与表定位作答
- **AND** 回答 MUST NOT 出现工具未返回的表或问题

#### Scenario: 按表名与级别过滤

- **WHEN** 用户追问某张表或某个严重级别的问题
- **THEN** agent MAY 以表名或级别作为参数再次调用问题清单工具

#### Scenario: 静音问题不参与回答

- **WHEN** 某条问题已被静音
- **THEN** 问题清单与统计 MUST 排除该问题，与现有问题清单、首页统计保持同一口径

#### Scenario: 输出受控

- **WHEN** 问题数量很多
- **THEN** 工具 MUST 只返回有限条数并截断单条说明，避免一次返回撑满模型上下文

#### Scenario: 记录实际调用的工具

- **WHEN** agent 在回答中调用了数据源概况、问题清单或表结构工具
- **THEN** 回答的 `tools_used` MUST 包含这些工具名，供使用者判断回答依据

### Requirement: 数据源问答界面

系统 SHALL 在问答页面提供数据源选择，与知识库选择、回答模式并列。选中的数据源 MUST 随提问提交，会话 MUST 持久化该选择并在重新打开时恢复；清除选择后 MUST NOT 继续使用旧数据源。

#### Scenario: 选择数据源并提问

- **WHEN** 用户在问答页面选择数据源后提问
- **THEN** 请求 MUST 携带该数据源的标识

#### Scenario: 重新打开会话恢复选择

- **WHEN** 用户重新打开一个曾指定数据源的会话
- **THEN** 页面 MUST 恢复该会话的数据源选择

#### Scenario: 清除数据源选择

- **WHEN** 用户清除数据源选择后继续提问
- **THEN** 本次提问 MUST NOT 使用该会话此前选中的数据源
- **AND** 后续提问 MUST 同样保持未指定状态

#### Scenario: 停用数据源可见

- **WHEN** 数据源已停用但仍存在
- **THEN** 选择列表 MAY 展示该数据源并标明停用状态，MUST NOT 静默隐藏
