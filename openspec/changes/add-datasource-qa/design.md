## Context

知识问答现状：

- 请求已支持可选的 `datasource_id`，但前端从不传，会话也不保存
- agent 只有一个数据源工具 `get_table_schema`：能列表、看表结构，但没有问题清单与整体概况
- 未选知识库时走 `_PATH_NO_KB` 直接用通用模型作答，数据源工具根本不会被构造
- 自动模式下知识库检索无命中会直接回退通用模型，同样绕开数据源
- `tools_used` 只从检索结果反推，数据源工具调用不会被记录

数据源侧已有稳定的跨模块读取入口：`datasource_services.latest_snapshot_data()`、`list_snapshot_tables()`、`muted_filter()`，问题与快照都在业务库内，读取不需要连接被纳管数据库。

## Goals / Non-Goals

- Goals:
  - 用户可以在一次会话中选定数据源，并围绕它提问表数量、表结构与健康问题
  - 数据源作为独立事实来源参与路由，而不是知识库的附属
  - 回答明确体现调用过哪些数据源工具
- Non-Goals:
  - 不新增问答模式；不改变现有三种模式的语义
  - 不连接被纳管数据库执行实时查询，只读最近一次快照与问题表
  - 不在消息级记录数据源（会话级即可）

## Decisions

### D1：数据源是可选上下文，不新增模式

模式仍是「自动 / 仅知识库 / 仅通用模型」。

- 自动：知识库（如有）与数据源（如有）都可作为依据
- 仅知识库：只允许知识库，不挂数据源工具
- 仅通用模型：两者都不用

这样不改变现有交互，也不让模式数量随来源增加而膨胀。

### D2：路由把数据源视为独立来源

`_prepare` 的路径判定调整为：

| 模式 | 知识库 | 数据源 | 路径 |
|------|--------|--------|------|
| 仅通用模型 | - | - | 直接问模型 |
| 仅知识库 | 必填 | 忽略 | agent（不挂数据源工具） |
| 自动 | 有 | 无/有 | agent（有数据源时预检索无命中仍进 agent） |
| 自动 | 无 | 有 | agent（仅数据源工具，不做向量检索） |
| 自动 | 无 | 无 | 直接问模型（保持现状） |

`_decide_after_hits` 在无命中时增加一条：已选数据源则仍进 agent，否则按原逻辑回退。

### D3：会话持久化 datasource_id，不建跨模块外键

`qa_session` 增加可空整数列 `datasource_id`，不建到 `datasource` 表的外键：

- 知识模块与数据源模块的边界通过 service 维持，不引入模型级依赖
- 数据源被软删除时，会话记录保留；提问时由 `datasource_brief()` 判存在性并给出明确错误

请求显式携带 `datasource_id`（含 `null`）时以请求为准，并同步更新会话默认值；未携带时沿用会话默认值。这样前端清除选择后不会继续使用旧数据源。

### D4：新增两个只读工具

- `get_datasource_summary()`：表数量、模式数量、问题总数与高/中/低分布、最近采集时间
- `list_catalog_issues(table_name, issue_level)`：问题明细，支持按表名与级别过滤，默认返回前 20 条

两者都只读最近一次快照；问题统计与清单都必须经过 `muted_filter()`，与现有问题清单、首页统计保持同一口径。工具返回给模型的文本设上限，避免一次把上下文塞满。

### D5：工具调用记录改为显式收集

现有 `_tool_names(collected)` 只能从检索片段反推 `search_knowledge_base`，新增工具不会被记录。改为构造工具时传入共享的 `used_tools` 列表，每个工具执行时写入自己的名字；`tools_used` 去重后返回。这样同步与流式两条路径都能如实展示。

### D6：前端选择与恢复

问答页新增数据源下拉，与知识库、模式并列：

- 列表来自现有 `/v1/datasource`，停用项带标记
- 提问时始终显式提交 `datasource_id`（未选为 `null`），使清除语义明确
- 打开会话时恢复 `datasource_id`
- 回答的工具标签沿用现有 `tools_used` 展示，无需新增组件

## Risks / Trade-offs

- 快照可能过期 → 概况工具返回最近采集时间，回答里可提示先重新采集
- 问题清单可能很长 → 默认 20 条、单条文本截断；需要更多时由用户追问并按表过滤
- 数据源被删除后会话仍引用 → 提问前明确报错，提示重新选择
- 仅会话级记录数据源 → 同一会话切换数据源后，历史消息不体现当时的选择；当前需求不要求消息级审计

## Migration Plan

1. `src/sql/pg_struct.sql` 的 `qa_session` 建表语句增加 `datasource_id integer NULL`
2. `src/sql/patch.sql` 追加 `ALTER TABLE qa_session ADD COLUMN IF NOT EXISTS datasource_id integer`
3. 已有会话该列为空，行为与未选数据源一致；不需要回填
4. 回滚：保留列不影响旧代码；前端与 agent 逻辑可独立回退
