# Change: 测试库预置（建库 + 造数，仅测试环境）

## Why

测试人员需要一套可直接使用的测试数据：表结构、字段类型、非空约束、外键引用顺序，手工建库与造数既慢又容易违反约束。现有能力只做到「生成 SQL」，执行仍要靠人，且没有地方记录「这个测试库是谁、什么时候、按哪些表建的」。

本能力把闭环补上，但**只允许在显式标记为测试环境的数据源上**新建独立数据库——生产数据源禁用，系统仍然不执行任何生产库变更。

## What Changes

- 数据源**创建/编辑时**由管理员指定**环境类型**（生产 / 测试，默认生产）与**独立的预置写账号**（建库 + DML，与只读采集账号分离，密码加密存储）
- 新增「测试库预置」能力：
  - 从最新快照选取表，生成同方言的**近似 DDL**
  - 按外键拓扑顺序生成数据并写入；**行数按表指定**
  - 按列名/注释做**简单语义推断**（邮箱、手机号、姓名、金额、编号、URL 等），类型不兼容或无法识别时回退到类型生成
  - 在目标服务器新建**唯一命名的独立 database**，绝不写入已有库
  - 执行前预览 DDL、行数与警告，二次确认后执行
  - 失败自动清理；支持删除由本功能创建的测试库
- 已创建且状态可用的测试库支持**后续维护**：向记录中的表追加数据、清空表数据、从最新快照新增表、删除本功能创建的表；操作后更新记录的表明细与行数
- 新增 `provisioned_database` 记录：创建人、数据源、库名、表、行数、状态、失败原因
- 数据源表单新增环境类型与写账号字段（创建者与管理员可见）；「测试库预置」页面放在「库表」组，登录用户只能对接自己创建的数据源
- 新增 `[provisioning]` 配置段（表数、行数、超时、快照最大年龄、库名前缀）

- 受影响能力：

  - `src/config/urls.py`、`src/config/conf.ini`

## 明确不做

- **不写生产库**：生产数据源没有预置入口，后端直接拒绝；不做任何生产库变更执行
- **不写已有库**：只新建独立 database；后续维护只作用于本功能创建且状态可用的测试库，不修改任何既有库
- **不做任意 SQL 执行**：后续维护只提供结构化的追加数据、清空数据、新增表、删除表，不接受任意 SQL
- **不做级联删除**：清空/删表不使用 `CASCADE`，被外键引用时如实失败
- **不复制数据**：只从快照读元数据，不读取源库任何业务数据
- **不保证完整结构**：CHECK、触发器、视图、序列、扩展、权限、分区定义不采集，因此不还原；生成的是近似结构
- **不做跨方言**：PG 快照建 PG 库、MySQL 建 MySQL 库
- **不做复杂业务语义与关联推断**：只按列名/注释做简单语义映射，生成值仍是合成数据，不保证业务正确；复杂规则、跨表业务关系不推断
