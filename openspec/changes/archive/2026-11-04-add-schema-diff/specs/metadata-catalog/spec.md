## MODIFIED Requirements

### Requirement: 元数据快照

系统 SHALL 以不可变快照保存每次采集结果，支持查询最新快照与历史快照列表，并 SHALL 支持对**任意两个快照**做结构差异对比。

对比结果 SHALL 同时给出两侧快照的元信息（所属数据源、数据库类型、采集时间、表数量、未采集项）与警告，使使用者能判断差异的可信度。

当两侧数据库类型不同时，对比 MUST 给出「类型名称天然不同，差异仅供参考」的警告，MUST NOT 做跨方言类型归一化。

对比 SHALL 支持可选的「按表名对齐」（忽略 schema）。当任一侧快照在多个 schema 下存在同名表时，MUST 拒绝该模式并列出冲突表名，MUST NOT 悄悄合并。

#### Scenario: 生成快照

- **WHEN** 一次采集成功完成
- **THEN** 系统生成一条带采集时间的快照记录并关联到该数据源

#### Scenario: 快照不可变

- **WHEN** 已有快照之后再次对该数据源采集
- **THEN** 新结果写入新快照，历史快照内容保持不变

#### Scenario: 快照差异对比

- **WHEN** 用户选择同一数据源的两个快照进行对比
- **THEN** 系统返回新增、删除、变更的表与列，以及索引的增删变化

#### Scenario: 跨数据源差异对比

- **WHEN** 用户选择两个不同数据源各自的最新快照进行对比
- **THEN** 系统 MUST 正常返回结构差异，并在响应中带出两侧数据源名称与快照采集时间

#### Scenario: 跨方言对比给出警告

- **WHEN** 参与对比的两个快照所属数据源类型不同（如 PostgreSQL 与 MySQL）
- **THEN** 响应 MUST 包含「类型名称天然不同，差异仅供参考」的警告
- **AND** MUST NOT 对类型名称做归一化处理

#### Scenario: 按表名对齐

- **WHEN** 用户启用「忽略 schema，按表名对齐」选项
- **THEN** 系统 MUST 以表名而非「schema.表名」匹配两侧表，并正常返回差异

#### Scenario: 同名表冲突时拒绝

- **WHEN** 启用按表名对齐，且任一侧快照在多个 schema 下存在同名表
- **THEN** 系统 MUST 拒绝对比并返回参数错误（code 4000），列出冲突的表名
- **AND** MUST NOT 把这些同名表悄悄合并为一张

#### Scenario: 未采集项如实提示

- **WHEN** 任一侧快照包含因权限或版本原因未采集的项
- **THEN** 对比响应 MUST 提示存在未采集项，说明对应结构可能被误判为差异

## ADDED Requirements

### Requirement: 结构对比界面

系统 SHALL 提供「结构对比」页面，允许使用者分别选择基准侧与对比侧的数据源与快照，并展示结构差异。

页面 SHALL 默认选中每个数据源的最新快照；两侧选中同一快照时 MUST 阻止对比并提示。

差异结果 MUST 按新增表、删除表、变更表分区展示；变更表 MUST 可展开查看列的新增 / 删除 / 变更（变更前后值）以及索引的增删。

页面 MUST 展示后端返回的警告（跨方言、未采集项、按表名对齐）；未选齐两侧、某侧尚未采集、已对比但无差异三种情况 MUST 给出各自明确的空态文案。

#### Scenario: 选择两侧快照进行对比

- **WHEN** 使用者为基准侧与对比侧分别选择数据源与快照并触发对比
- **THEN** 页面 MUST 展示新增 / 删除 / 变更表的数量与明细

#### Scenario: 默认最新快照

- **WHEN** 使用者选择一个数据源
- **THEN** 该侧快照下拉 MUST 默认选中最新快照

#### Scenario: 变更表可展开

- **WHEN** 使用者展开一张变更表
- **THEN** MUST 展示新增列、删除列、变更列（含变更前后签名）与索引的增删

#### Scenario: 跨方言警告可见

- **WHEN** 两侧数据源类型不同
- **THEN** 页面 MUST 展示「类型名称天然不同，差异仅供参考」的警告

#### Scenario: 同一快照不可比较

- **WHEN** 两侧选择了同一个快照
- **THEN** 页面 MUST 阻止对比并提示选择不同的快照

#### Scenario: 无差异时如实说明

- **WHEN** 对比完成且两侧结构完全一致
- **THEN** 页面 MUST 明确说明「两个快照之间没有结构差异」，MUST NOT 留白

### Requirement: 采集变更摘要

系统 SHALL 在每次采集成功时，把本次结果与同一数据源的**上一次快照**做结构对比，并把紧凑摘要保存在新快照上。

摘要 MUST 至少包含是否可比、基准快照标识与采集时间、新增 / 删除 / 变更表的数量、是否存在变化。

首次采集（没有上一次快照）MUST 记录为「不可比」并说明原因。摘要计算失败 MUST NOT 导致采集失败，且 MUST 记录为「不可比」及原因，MUST NOT 伪装成「无结构变化」。

采集任务接口 SHALL 返回该摘要。历史快照没有摘要时 MUST 返回「未记录」，MUST NOT 返回「无变化」。

#### Scenario: 采集后生成摘要

- **WHEN** 对已采集过的数据源再次采集并成功
- **THEN** 新快照 MUST 保存与上一次快照的差异摘要，包含各计数与是否有变化

#### Scenario: 首次采集不可比

- **WHEN** 数据源首次采集成功
- **THEN** 摘要 MUST 标记为不可比，并说明「首次采集，没有上一次快照」

#### Scenario: 摘要计算失败不影响采集

- **WHEN** 摘要计算过程中发生异常
- **THEN** 采集任务 MUST 仍然成功，摘要 MUST 标记为不可比并说明计算失败
- **AND** MUST NOT 把该快照显示为「无结构变化」

#### Scenario: 任务接口返回摘要

- **WHEN** 查询某数据源的采集任务列表
- **THEN** 每个成功的任务 MUST 带出对应快照的变更摘要；没有快照的任务 MUST 返回空值

#### Scenario: 历史快照无摘要

- **WHEN** 快照是在本能力上线之前生成的
- **THEN** 接口 MUST 返回「未记录」语义的空值，前端 MUST NOT 显示「无结构变化」
