# 设计：测试库预置

## Context

系统此前对目标库只有读路径（采集、试运行）和「只生成不执行」的写建议。本能力引入**第一条对目标库的写路径**，因此设计重点不是建库本身，而是把「绝不能碰生产库和已有库」做成后端硬约束。

## Goals / Non-Goals

- Goals：在测试环境快速得到一套可用的库表与测试数据；过程可预览、可审计、可清理
- Non-Goals：生产库变更、已有库写入、完整结构还原、业务语义数据、跨方言迁移

## Decisions

### 环境类型默认生产，必须显式改为测试

`datasource.env_type` 取 `production(1)` / `test(2)`，**默认 production**。历史数据迁移后全部是 production，预置功能对它们不可用；管理员必须显式把目标数据源标记为测试。这样「漏配」的结果是功能不可用，而不是误操作。

后端在预置入口再次校验 `env_type == test`，不能只依赖前端隐藏。

### 预置写账号与采集账号分离

数据源增加 `write_username` / `write_password`（Fernet 加密），与现有只读采集账号完全独立。未配置写账号时预置功能不可用。所有响应可返回写用户名与 `has_write_credential` 布尔值，**写密码永不返回**。

**环境类型与写账号在数据源创建/编辑时设置**，不另设「预置配置」页：

- 表单字段对**数据源创建者与管理员**可见；其他用户提交这些字段返回 4005
- 这样配置与数据源本身放在一起，避免「数据源列表里看不到、要去另一个页面配」的割裂
- 预置页只负责选库、预览、执行与清理，不再承担配置职责

### 按数据源归属控制权限

预置对所有登录用户开放，但**只能操作自己创建的数据源**与自己的预置记录；管理员可操作全部。这是现有的最小权限模型：

- 数据源本身已有 `creator` 字段，直接用它做归属判断，不发明新的权限表
- 普通用户的预置页数据源下拉只列自己创建的数据源；后端再次校验，不能靠前端过滤
- 预置记录按 `creator` 隔离：普通用户只看到、只删除自己的记录；管理员可查看和删除全部
- 更细的数据源协作权限留给后续「数据源级权限」能力

### 库名由服务端生成，只新建不覆盖

库名格式固定为 `{prefix}_{datasource_id}_{YYYYmmddHHMMSS}_{4位随机十六进制}`，前缀来自 `[provisioning] db_prefix`，默认 `dba_test`。预览接口返回本次将使用的库名；执行接口校验该名称符合格式且数据源为测试环境后创建。

- `CREATE DATABASE` 遇到同名库会失败，**绝不覆盖已有库**
- 执行记录写入 `provisioned_database`；删除接口只接受该表里的记录，不接受任意库名

### 从快照生成近似 DDL

只创建使用者勾选的表，按 PG / MySQL 各自的方言生成：

- 列：名称、类型、长度、`NOT NULL`、可解析的默认值
- 主键、唯一索引、普通索引
- 外键：**仅当被引用的表也在本次选择中**才创建；否则跳过并明确警告
- `nextval(...)` 一类序列默认值不还原，主键值由造数阶段显式提供
- 不支持的类型（数组、自定义枚举、空间类型等）在预览阶段如实拒绝该表，不猜测

**不创建** CHECK、触发器、视图、序列、扩展、权限、分区定义——快照里没有这些信息。界面必须常驻提示「这是近似结构」。

### 造数按外键拓扑顺序，行数按表指定

- 先父表后子表；外键值取自已生成的父表行
- 循环外键与不可空的自引用外键在预览阶段拒绝并说明原因，不产出可能失败的数据
- 每张表 MUST 支持独立设置行数；受每表上限与总量上限共同约束
- 满足主键唯一、唯一索引、`NOT NULL`、类型与长度
- 使用固定随机种子（可选传入；不传则服务端生成并返回），便于复现
- 分批参数化插入，不拼接原始值字符串

### 简单语义推断

按**列名与注释**做启发式映射，覆盖常见字段：

| 语义 | 识别关键词（示例） | 生成策略 |
|------|------------------|---------|
| 邮箱 | email、mail、邮箱 | `test{行号}@example.com`，唯一约束下自动加后缀 |
| 手机号 | phone、mobile、手机、电话 | `1380000{行号后四位}` |
| 姓名 / 名称 | name、姓名、名称 | `测试用户{行号}` / `测试数据{行号}` |
| 用户名 | username、user_name、用户名 | `test_user_{行号}` |
| 金额 / 价格 | amount、price、money、金额、价格、费 | 两位小数的随机金额 |
| 编号 / 编码 | code、no、编号、编码 | `CODE{行号补齐}` |
| URL | url、链接、网址 | `https://example.com/{行号}` |
| IP | ip、IP地址 | `192.0.2.x`（TEST-NET-1 文档地址） |
| 状态 | status、状态 | 小范围离散值（如 0/1/2） |
| 标题 / 备注 / 地址 | title、remark、description、地址 | 对应前缀的合成文本 |

约束：

- 仅当**类型兼容**时使用语义生成（如金额只用于数值列、邮箱只用于字符列）；不兼容时回退到类型默认生成
- 语义值同样受长度、唯一索引与 `NOT NULL` 约束；长度不足时截断并保持唯一
- 语义推断是**启发式**：不保证业务正确，不推断单位、精度、业务规则或跨表关联；界面与文档必须如实说明
- 同一数据源、表集合、行数与种子 MUST 产生相同结果

### 预览与执行两阶段，执行有硬限制

- `POST /test-db/preview`：只生成计划（库名、DDL、行数、警告），不连接目标库、不落库
- `POST /test-db/provision`：要求 `confirm=true`，服务端重新校验环境、凭据、名称与限制后再执行
- 限制来自 `[provisioning]`：最大表数、每表最大行数、总行数、执行超时、快照最大年龄
- 快照超过最大年龄时给出警告，但不阻止（测试环境可能很久没采集）

### 已创建测试库的后续维护

预置完成后，创建者/管理员可以在记录里继续维护：

- **追加数据**：只针对记录中的表；外键值从测试库现有父表读取，父表无数据时拒绝；唯一冲突整体回滚
- **清空数据**：`DELETE`，不做 `CASCADE`；被外键引用时由目标库拒绝
- **新增表**：只从最新快照选表；外键只指向测试库中已存在的表；MySQL DDL 不可回滚，失败时尝试删掉新表
- **删除表**：只允许删除记录中的表；`DROP TABLE` 不带 `CASCADE`
- 每次操作后按测试库实际行数刷新记录的表明细与总行数

维护操作只接受结构化参数，**不接受任意 SQL 或任意库名**；记录状态必须是 `ready`，且操作者必须是记录创建者或管理员。

### 失败清理与审计

执行前先写入 `provisioned_database`（状态 `creating`）；成功置 `ready`，失败置 `failed` 并尽量 `DROP DATABASE` 清理半成品。

- PG：`CREATE DATABASE` 不能在事务里；失败后连接回管理库尝试删除
- MySQL：DDL 不可回滚；失败后尝试 `DROP DATABASE`
- 清理失败时保留记录与失败原因，管理员可再次调用删除接口
- 审计信息即 `provisioned_database` 记录；同时写 `provisioning.log`，日志不含任何凭据

### 模块归属

新增 `apps/provisioning/`，通过 `datasource.services` 读取快照与数据源信息，不直接 import 数据源模型；写账号解密通过 `datasource.services` 的专用契约返回加密串，由 provisioning 模块用 `utils.crypto` 解密，避免跨模块直接查表。

## Risks / Trade-offs

| 风险 | 处理 |
|------|------|
| 误把生产标记为测试 | 默认生产；入口二次校验；管理员二次确认；创建的是独立新库，不触碰已有库 |
| 写账号权限过大 | 独立账号、仅数据源创建者与管理员可配置；文档要求专号专用 |
| 结构不完整导致测试结果失真 | 界面常驻「近似结构」提示；明确列出未还原项 |
| 外键循环 / 自定义类型 | 预览阶段拒绝并说明，不产出不可用库 |
| 失败残留数据库 | 自动清理 + 记录失败库名 + 可重试删除 |
| MySQL DDL 不可回滚 | 失败按删库处理；记录状态供人工兜底 |
| 造数耗时长 | 表数 / 每表行数 / 总行数 / 超时四重限制 |
| 语义推断被误当成业务正确 | 文档与界面标注「启发式、合成数据」；类型不兼容时回退；不推断业务规则 |

## 已确认

- 行数按表指定（受每表与总量上限约束）
- 生成值按列名/注释做简单语义推断（类型不兼容时回退），不做复杂业务规则

## Migration Plan

1. 执行 `src/sql/patch.sql` 增量：数据源新列（默认生产）、`provisioned_database` 表
2. 部署后端与前端
3. 管理员在数据源编辑页把测试数据源标记为 test 并配置预置写账号
4. 生产数据源无需任何操作，保持不可用
