# 设计：测试数据文件导出

## Context

测试库预置需要测试环境、独立写账号并真实写目标库；部分使用者只需要一份数据文件，由自己导入到受限环境。该能力只读快照、生成文件，不引入新的写入路径。

## Goals / Non-Goals

- Goals：生成可直接下载的 SQL 数据文件；与测试库共用同一套造数规则
- Non-Goals：执行导入、连接目标库、生成任意 SQL、保证完整结构

## Decisions

### 文件生成与测试库共用造数逻辑

复用 `apps/provisioning/data.py` 的语义推断、类型/长度/非空/唯一/外键处理和 `ddl.py` 的标识符与建表逻辑，避免两套造数规则逐渐分叉。行数上限沿用 `[provisioning]`。

### 只读快照，不要求测试环境或写账号

测试数据文件不写入任何库，因此：

- 普通用户只能选择自己创建的数据源；管理员可选全部（沿用数据源归属）
- **不要求环境类型为测试，也不要求配置预置写账号**——生产库的结构也可以导出数据文件，供测试环境使用
- 不连接目标库，不读取源库业务数据

### 手动输入表结构

不要求先关联数据源，使用者可以直接粘贴 DDL：

- 复用 `apps/ddlreview` 的解析与合并（纯计算模块）：`parser.parse_ddl` + `merge.apply`
- 只接受 `CREATE TABLE` / `CREATE INDEX` / `ALTER TABLE`；注释语句忽略并提示，`DROP` / `TRUNCATE` / 视图等直接拒绝，避免把「删表」当成结构定义
- 未限定 schema 的外键按子表 schema 归一，保证拓扑排序能匹配父表
- 手动模式不依赖数据源，因此没有数据源归属限制；任何登录用户都可生成
- 仍受表数/行数上限约束；生成的数据与文件格式与数据源模式一致
- 手写 DDL 的列/表注释不被解析，语义推断只能依据列名

### SQL 文件格式

- 头部注释：数据源、快照时间、表数量/行数、生成时间、警告、导入提示
- 可选 DDL：复用 `ddl.build_plan` 的建表/索引/外键语句（不含 `CREATE DATABASE`）
- 数据：按外键拓扑顺序生成；每 100 行一条多行 `INSERT`
- 值按方言渲染为 SQL 字面量：字符串单引号转义、MySQL 额外转义反斜杠、布尔按方言、时间/日期/JSON/二进制分别处理
- MySQL 文件头部提示先 `USE` 目标数据库
- 不自动包 `BEGIN/COMMIT`：MySQL DDL 不可回滚，统一包事务会误导；导入方式由使用者决定

### 未选中的被引用表必须警告

若所选表的外键引用了未选中的表，生成的外键值可能无法通过目标库校验。文件与接口响应都给出明确警告，**不静默生成**。

### 菜单结构

顶层「造数」（位于 SQL 下方）→ 子菜单「数据文件」「测试库」（数据文件在上）。数据文件的数据源模式按数据源归属控制：普通用户只看到自己创建的数据源；手动表结构模式不依赖数据源。

## Risks / Trade-offs

| 风险 | 处理 |
|------|------|
| 使用者把文件导入错误环境 | 文件头写明数据源与「请确认目标环境」；系统不执行导入 |
| 生成结构与源库有差异 | 与测试库相同的近似结构说明；可选 DDL 也注明不还原 CHECK 等 |
| 外键值无法通过目标库校验 | 未选中父表时明确警告 |
| 文件过大 | 沿用表数/单表行数/总行数上限；INSERT 分批 |
| 敏感数据 | 不读取源库数据，生成值全部为合成数据 |

## Migration Plan

无需 DDL；部署后端与前端即可。菜单入口变化不影响既有接口。
