# 测试库预置（建库 + 造数）

在**测试环境**的数据源上，从最新元数据快照生成一套近似结构，并按外键顺序写入测试数据。系统会新建一个**独立 database**，不会写入任何已有库。

对应模块：`src/apps/provisioning/`（`ProvisioningView`，登录用户可用）。

> 这是系统**唯一**会对目标库执行写操作的路径。生产数据源没有入口，服务端也会拒绝。

**权限**：登录用户都可以使用，但只能操作**自己创建的数据源**和自己的预置记录；管理员可操作全部。菜单位于**「造数 → 测试库」**。

## 安全边界

| 做 | 不做 |
|----|------|
| 在显式标记为**测试**的数据源上新建独立 database | 生产数据源预置（服务端拒绝） |
| 使用独立的预置写账号建库与 DML | 复用只读采集账号、读取源库业务数据 |
| 从快照生成近似结构与合成数据 | 还原 CHECK / 触发器 / 视图 / 序列 / 扩展 / 权限 |
| 预览后二次确认再执行 | 修改、删除或写入已有 database |
| 失败自动清理，保留记录 | 自动执行任何生产库变更 |

环境类型默认是**生产**，历史数据源迁移后全部不可预置；必须由管理员显式改为测试并配置写账号。

## 使用流程

1. 在「数据源管理」中**新建或编辑**测试数据源：环境类型选「测试」，填写**独立的预置写账号**（建库 + DML 权限）；这两个字段对数据源创建者与管理员可见
2. 进入「造数 → 测试库」，选择自己创建的数据源
3. 勾选表、**逐表设置行数**（可选设置随机种子）
4. 点击「预览」：查看将创建的库名、DDL、总行数与警告
5. 勾选确认后点击「执行预置」
6. 在「已创建的测试库」列表中查看状态；不再需要时删除

## 已创建测试库的后续维护

「已创建的测试库」Tab 展开一条记录可以看到表清单，并对状态为「可用」的库继续操作：

| 操作 | 说明 |
|------|------|
| **加数据** | 向记录中的表追加指定行数；外键值从测试库现有父表读取；唯一冲突时整体回滚 |
| **清空数据** | `DELETE` 表内全部数据；不使用 `CASCADE`，被外键引用时会失败 |
| **新增表** | 从源库最新快照选择尚未在记录中的表，建表并造数；外键只指向测试库中已存在的表 |
| **删表** | 只允许删除记录中的表；不使用 `CASCADE`，被外键引用时会失败 |

维护完成后记录里的表行数与总行数会按测试库实际数据刷新。维护接口只接受结构化参数，不接受任意 SQL。

## 近似结构与数据

### 会还原

- 列名、类型、长度、`NOT NULL`、可安全还原的默认值
- 主键、唯一索引、普通索引
- 外键（**仅当被引用表也被选中**；否则跳过并警告）
- PG 的 schema（`public` 之外会创建）

### 不会还原

CHECK 约束、触发器、视图、序列、扩展、权限、分区定义、自定义类型、数值精度等快照未采集的信息。因此：

- 创建出来的是**近似结构**，界面常驻提示
- 逻辑删除、审计字段等业务规则不会自动出现
- 复杂 CHECK 条件下，生成的数据即使写入了，也不代表满足原库的业务约束

### 造数规则

- 行数**按表指定**；受单表上限与总量上限约束
- 按外键拓扑顺序生成，先父表后子表
- 满足主键唯一、唯一索引、`NOT NULL`、类型与长度
- 循环外键、不可空的自引用外键在预览阶段拒绝
- 固定随机种子可复现；未提供时服务端生成并返回
  - **随机种子**：相同数据源、表、行数与种子会生成相同的数据；不填则每次随机
- 生成值是**合成数据**，不读取源库数据

### 简单语义推断

按列名与注释做启发式映射，类型不兼容时回退到类型默认生成：

| 语义 | 关键词示例 | 生成示例 |
|------|-----------|---------|
| 邮箱 | email / mail / 邮箱 | `test1@example.com` |
| 手机号 | phone / mobile / 手机 | `13800000001` |
| 姓名 / 名称 | name / 姓名 / 名称 | `测试用户1` |
| 用户名 | username / 用户名 | `test_user_1` |
| 金额 | amount / price / 金额 | `1.25` |
| 编号 | code / 编号 | `CODE00000001` |
| URL | url / 链接 | `https://example.com/1` |
| IP | ip / IP地址 | `192.0.2.1` |
| 状态 | status / 状态 | `0/1/2` |

语义推断不保证业务正确，也不推断业务规则或跨表关联。

## API

前缀 `{SYS_NAME}/v1/test-db`，要求登录。普通用户只能操作自己创建的数据源与记录；越权访问返回 4005；管理员可操作全部。

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/preview` | 生成计划（库名、DDL、行数、警告），**不连接目标库** |
| POST | `/provision` | 执行预置；要求 `confirm=true`，重新校验环境与限制 |
| GET | `/` | 预置记录列表（分页） |
| DELETE | `/{id}` | 删除本功能创建过的测试库 |
| POST | `/{id}/rows` | 向记录中的表**追加数据**（`schema` / `name` / `rows` / 可选 `seed`） |
| DELETE | `/{id}/rows?schema=&name=` | **清空**记录中某张表的数据 |
| POST | `/{id}/tables` | 从最新快照**新增表**并造数 |
| DELETE | `/{id}/tables?schema=&name=` | **删除**本功能创建的某张表 |

维护操作只作用于**本功能创建且状态为可用**的测试库；普通用户限自己的记录，管理员可操作全部。结构化的维护接口不接受任意 SQL 或任意库名。

环境类型与预置写账号通过**数据源的创建/编辑接口**设置（见 [datasource.md](datasource.md)），预置接口不提供单独配置入口。普通用户提交这些字段会被拒绝（4005）。

预览响应要点：

```json
{
  "db_name": "dba_test_1_20261105173000_abcd",
  "seed": 123456,
  "total_rows": 500,
  "create_database_sql": "CREATE DATABASE \"...\"",
  "statements": ["CREATE DATABASE ...", "CREATE TABLE ...", "..."],
  "tables": [{"schema": "public", "name": "orders", "rows": 100, "semantic_columns": []}],
  "warnings": ["..."],
  "snapshot_collect_time": "2026-11-01 10:00:00"
}
```

## 配置

`src/config/conf.ini` 的 `[provisioning]` 段：

| 键 | 默认 | 含义 |
|----|------|------|
| `db_prefix` | `dba_test` | 新建库名前缀 |
| `max_tables` | 20 | 单次最多选择的表数 |
| `max_rows_per_table` | 1000 | 单表最大行数 |
| `max_total_rows` | 5000 | 单次总行数上限 |
| `timeout_seconds` | 120 | PG 语句超时；MySQL 连接读写超时 |
| `snapshot_max_age_days` | 7 | 快照超过该天数时给出警告（不阻止） |

## 记录与审计

每次预置在 `provisioned_database` 表记录：

- 数据源、库名、选中的表与每表行数、写入行数
- 状态：`creating` / `ready` / `failed` / `dropped`
- 失败原因、发起人、时间

删除接口只接受该表里记录的库名，不接受任意库名。普通用户只能看到和删除自己创建的记录，管理员可管理全部。审计日志写入 `provisioning.log`，不包含任何密码。

## 已知限制

- **仅支持同方言**：PG 快照建 PG 库、MySQL 建 MySQL 库
- **MySQL DDL 不可回滚**：失败按「删掉半成品库」处理；清理失败时会保留库名与原因
- **PG `CREATE DATABASE` 不能在事务里**：建库与建表分两步，失败后连接回管理库清理
- **目标库版本差异**：快照里的类型语法按目标库自身方言使用；跨版本行为需实测
- **外键循环/不可空自引用**：无法确定插入顺序，预览阶段直接拒绝
- **不含数据导出**：不读取、不复制源库任何业务数据

## 部署前提

1. 执行 `src/sql/patch.sql` 中 `add-test-db-provisioning` 段的增量 DDL
2. 给测试数据源配置的写账号授予：建库（PG `CREATEDB` / MySQL `CREATE`）与目标库的 DDL/DML 权限
3. 不要复用只读采集账号；写账号仅用于本功能
